# SPEC-11 — Local versioned work packets

- **Status:** Implemented for [#597](https://github.com/true-line/cartograph/issues/597); release remains subject to PR validation and review.
- **Date:** 2026-10-19
- **Scope:** US-0037 / AC-0248–0252; ADR-0036 decisions 4, 5, 6 and 9.
- **Dependencies:** #584 producing method, #585 omission taxonomy, #586 artifact identity.

This specification defines AP-1a, the first local work-packet delivery under [SPEC-01](SPEC-01_context-hub.md) and [ADR-0036](adr/ADR-0036-lifecycle-reconstruction-direction.md). Packet types and commands below describe the local implementation; they do not authorize execution or claim completed real-provider acceptance. Existing APIs are identified explicitly. The body, lineage and source-freshness boundaries were cross-reviewed with the mechanical-contract owner; implementation and the field-level specification receive PR review before release.

## Scope and dependency contracts

Generate one immutable, locally reviewable change packet from explicit user intent and selected recovered evidence. Reopen and export the same body. Curated context is explicitly unavailable; no private overlay, discovery, synthesis, publication, model invocation, target write or worker execution is included. Execution remains `unoffered`; capability requests confer no authority.

Consume #584 `core_prov::ProducingMethod` verbatim: rule `{kind,rule,version}`, model `{kind,model}`, human `{kind,actor}`, or unrecorded. Preserve legacy absent serialization; never derive method from tier/extractor. Consume #585 `core_graph::omission::Omission {class,seam,detail}`: classes `unsupported_extractor|missing_input|unresolved_relationship|contradictory_or_stale|product_gap`; seams `adapter|registry|manifest_input|interpretation|requirement`. Do not introduce substitute enums. Consume #586 `SpecArtifact.schema`, `content_id` and `verify_identity()`. Its full content identity covers schema/id/filename/title/format/content/assertions, including assertions omitted from previews. Preserve export mode separately. The implementation consumes these dependency contracts.

## Body schema

`PacketBody {schema_version:1, identity, intent, evidence, work, acceptance, handoff, return}` has exactly seven groups and rejects unknown protocol fields. Source-authored fact properties remain arbitrary JSON admitted under bounds. Every required knowledge field uses `Known<T> = {state:"supplied",value:T,origin:Origin} | {state:"missing",omission:Omission}`. No null, empty string or empty required list silently represents missing information. `Origin` is `requested_intent` or `evidence`, with explicit local evidence IDs for the latter. Supplied user text is a request/claim, never recovered confirmation.

| Group | Fields and meaning |
|---|---|
| identity | `generator_version`, `template_version` (nonempty version strings); `application` (target application/system-manifest identity when supplied, otherwise an explicit missing binding); `recovered_basis` (view exactly `recovered_graph`, snapshot ID); `sources[]` (host registration ID, repo key, revision binding or missing omission); `configuration[]` (named relevant input, exact supported schema/content binding or missing omission); `input_closure` (missing unless producer support establishes it); `curated_context` (missing with explicit H3 limitation). Artifact schema/content bindings reside with complete artifact evidence below. |
| intent | Required `objective`, `expected_outcome`, `current_behavior`, `intended_behavior`, `scope`, `non_goals`, `business_rationale`, each `Known`; optional requested actor/journey remain absent unless explicitly supplied. Record `requested_by` as an optional user-supplied label, without asserting authenticated identity. No actor/journey/requirement synthesis. |
| evidence | `facts[]`, `artifacts[]`, `source_excerpts[]`, `interpretations[]`, `limitations[]`. Each has a stable packet-local ID derived from its typed reference and bound content, never a selection ordinal or generation timestamp. Limitations carry field/evidence pointers and shared Omission. Preserve contradictions; do not select a winning interpretation. |
| work | Required `affected_components`, `proposed_approach`, `dependencies`, `open_decisions`, each `Known`. Components name registered repositories and optional paths/fact references; they grant no filesystem authority. Dependencies are explicit set-valued text/references. Approach and decisions remain ordered user proposals with uncertainty. |
| acceptance | Required `positive_cases`, `negative_cases`, `proposed_verification`, each `Known`. Cases/procedures have local IDs, ordered steps, expected evidence and references. Separate arrays `discovered_tests`, `structural_test_associations`, `execution_evidence`, `coverage_evidence`, `assertion_support` preserve these distinct meanings. Each observation cites exact supplied evidence; absent arrays explicitly mean none supplied, not none exists. A name/procedure cannot fill execution/coverage/support fields. |
| handoff | Required `requested_capabilities`, `checkout_boundaries`, `tool_and_egress_requests`, `budgets`, `proposed_role`, `authorization_references`, each `Known`. Text/budgets are requests; authorization references cite supplied external records and never constitute a grant. No executable command field or dispatch route. |
| return | `implementation_revision`, `pull_request`, `execution_receipts`, `source_configuration_changes`, `reingest_comparison`, `residual_gaps`, each `Known`; default missing with field-specific omission. #597 does not create producer receipts or claim worker completion/success. Supplied historical material retains its actual provenance and limitations. |

A fact entry is `{id,reference,expected_digest,fact,provenance,provenance_problem,source_association,review_annotations}`. `reference` reuses the typed node ID or directed `(source,label,destination)` shape, never concatenated assertion text. `fact` contains the complete selected host node/edge; `expected_digest` reuses `node_digest`/`edge_digest`. Validated provenance preserves original tier/confidence/evidence/extractor/content hash/method. Invalid provenance stays explicitly invalid/Gap in presentation; retain original properties, never relabel invalid provenance confirmed.

`source_association` is the exact existing `SourceBinding` or a missing Omission. Excerpts record typed fact, receipt ID, range role/index, exact `CaptureSpanRef`, and retained text. Unsupported historical text is missing; working-tree text never substitutes. Supplied artifacts retain complete verified `SpecArtifact`, mode and ID/schema/content ID. An artifact that exceeds construction/output budget instead retains the requested `(id,schema,content_id,mode)` as an explicitly unverified omitted reference with `missing_input/interpretation` and a budget-exceeded detail. It is never supplied artifact evidence; no exact complete size or successful identity verification is claimed. Other selected evidence may still produce a draft. Native assertion occurrence/subject strings are retained as native fields; do not parse them into typed fact keys. Interpretations contain verbatim text, origin, support references, and original review/freshness/conflict labels or explicit unknowns; they create no curated projection or confidence promotion. Host-resolved `review_annotations` retain bounded existing decision-record content and its exact reviewed provenance/content hash. Associate only through a validated, unique match to the selected typed fact; ambiguous legacy subject strings produce an omission. Browser assertions cannot supply accepted/rejected authority. Annotations are immutable evidence as of generation; packet review is the separate mutable CAS record. A decision on changed content remains historical/stale, never silently applied to the replacement. Explicit historical decision selections are permitted by exact content hash and expected complete-record hash; the host reads them through the same bounded selection API. Retain their original reviewed assertion even when its hash differs from the current fact. Show a stale relationship only where the typed subject association is uniquely established; otherwise retain the historical record with an unresolved-relationship omission, never silently drop it or apply it to newer content.

## Selection and assembly

Generation request: `{expected_snapshot_id, facts:[{reference,expected_digest}], artifacts:[{id,schema,content_id,mode}], interpretation_decisions:[{content_hash,expected_record_hash}], intent,work,acceptance,handoff,return,supersedes?}`. Browser-supplied graph/provenance bodies are forbidden. Selection with both facts and artifacts empty fails; missing intent may produce an incomplete draft. Semantically equal duplicate selections normalize; conflicting duplicate keys fail.

Use existing `read_source_selection_snapshot_bounded` to copy graph plus associations in one transaction, then construct `ContextSnapshot` from that same owned copy. Match expected snapshot and all selected digests. Acquire source/retention guards from host registration, then authoritatively recheck graph and associations. Reuse `task_guard/task_receipt/task_text` for pinned exact historical ranges, checking registration/repo/fact/digest/receipt/occurrence. A missing binding adds a limitation rather than falling back to `legacy_text` or current `describe/read`.

Compile artifacts from the same owned graph and captured projection inputs. Verify identity from the deserialized typed artifact using `SpecArtifact::verify_identity()`, never by hashing canonical packet-body bytes, and compare the entire expected `(id,schema,content_id)` before retention. A preview/full mismatch returns `selection_conflict`; never attach preview identity to newer content. Capture the complete effective compiler rejection set once and resolve annotations from that same bounded observation, then recheck the rejection set and relevant decision content; a detected change during generation returns selection conflict. A changed expected full artifact identity also conflicts. An unrelated historical decision update with no effect on selected artifacts is not by itself a conflict with the earlier preview. Bind supported configuration; no cross-store atomicity is implied. Existing `DecisionLog::list_assertions` is unbounded, so packet assembly needs bounded selected-decision reads rather than materializing the whole log. The selected-read API accepts at most 64 raw exact lowercase-hex content hashes before duplicate normalization, returns sorted entries including explicit missing records, and reads the complete selection in one SQLite read transaction. It admits each stored row by its UTF-8 byte lengths before allocating its text (16 KiB per row, 128 KiB cumulative and serialized result), validates the existing assertion contract and requires its embedded hash to match the requested database key. Oversized, corrupt or mismatched selected rows fail explicitly; irrelevant rows are never loaded. For artifact compilation, a companion observation scans the complete decision log in one read transaction, validates each row through the existing assertion contract, and retains only the effective rejected hashes and requested decision records. Admit at most 50,000 rows and 32 MiB cumulative stored text, with the same 16 KiB per-row ceiling, before reading owned row text. This scan must not materialize the whole decision history. Its selected-record result retains the 128 KiB limit; malformed or oversized curation state fails explicitly rather than silently changing projection policy. These reads report historical decisions, not proof of a unique typed graph identity; host assembly still validates that association. Reject incoherent/racing bases. Artifact materialization must be budgeted during construction, including assertion lists; checking only after an arbitrarily large full compile is insufficient. Artifact tracing uses a shared bounded traversal entry point with caller-supplied maximum flow count, hop count and serialized owned output bytes. Admit candidates before allocating owned hop names/provenance, and bound temporary fan-out with borrowed candidates. Within limits, bounded and ordinary traversal serialize identically, including anchor coverage, reversed edges, deduplication, narrative/LIFO order, depth-limited status and floating-point score summation. Resource overflow returns an explicit limit error; it never silently produces an apparently complete shortened flow. Linear indexes over the already-admitted snapshot are allowed; ADR drift cross-products require separate per-occurrence/byte admission before deriving owned findings. Shared fallible renderers admit output and large formatting temporaries before allocation, and skip unselected sibling artifacts.

## Canonical identity and storage

The `work-packets` crate owns packet types, canonical encoding and local persistence boundaries. Its bounded encoder streams from an admitted JSON value without cloning the tree or constructing unbounded escaped strings; limits include output bytes, depth, total values and per-object keys before sorting. Canonical UTF-8 JSON recursively orders object keys bytewise by UTF-8 and preserves exact strings and meaningful array order, using serde_json number formatting. This is a project canonical form, not RFC 8785/JCS. Normalize declared unordered collections only: facts by typed key, artifacts by `(id,mode)`, source/configuration bindings by stable key, set-valued dependencies by canonical value, selected excerpts by typed fact/receipt/range identity, and host-resolved review annotations by immutable record/content identity. Identical duplicates collapse; conflicting duplicates fail. Generate packet-local evidence IDs deterministically from normalized typed/content keys, never request arrival indexes; collect host-derived excerpts/annotations in normalized fact/receipt-occurrence order. Procedure/case/narrative order remains meaningful. Use domain-separated BLAKE3: `work-packet-v1:` plus hash of `cartograph:work-packet:v1\0` followed by canonical body bytes. Packet ID is outside the body. Generator/template versions, intent, exact cited ranges/text, configuration bindings and full artifact content identities are covered.

Packet generation/check/review timestamps, mutable review/freshness state and lineage are outside canonical body identity. Preserve selected upstream fact properties and their existing content digests verbatim; this rule does not strip original provenance timestamps from evidence. Changed body creates a new ID. Regeneration may reuse identical body without resetting review.

Dedicated local store tables own immutable bodies, generation events, immutable `supersedes` edges and revisioned reviews. On every reopen, admit only the exact owned SQLite table/trigger/index definitions and singleton schema-version row; refuse partial, altered or unsupported schemas without repairing missing guards. Validate bounds and recomputed body identity when loading saved packets. Lineage insertion requires existing predecessors, rejects self-links/cycles, and is transactional; an existing edge cannot be rewritten. Same body may acquire distinct predecessor edges/events without changing identity. Lineage is outside the reviewed body: adding a predecessor does not change review revision or mean that the existing review approved that link. Preserve all historical bodies; no automatic deletion in this slice. Generation, review and assessment events form an append-only local audit log; repeated operations grow database size without a retention or pruning bound in this slice. The current API does not expose event-history reads; retention and inspection policy remain follow-up work.

Review starts `{revision:0,status:draft,note:null}`. Review request `{packet_id,expected_revision,decision:reviewed|changes_requested,note?}` updates one row and appends its event within an immediate transaction. Update only where revision equals expected; increment once. Otherwise return `review_conflict` with current revision/status. Review never mutates body, source binding, lineage, producing tier/confidence or freshness.

## Independent freshness

Assessment is separate metadata: `{packet_id,checked_at,state:current|stale|conflicted|unknown,observed_snapshot_id?,checks[],limitations[]}`. Checks independently identify graph, associations, registration/revision, retained integrity, live full-file bytes, membership and configuration/closure, with `equal|changed|unavailable|unsupported|raced` results. No review decision changes these results.

Pinned historical integrity remains inspectable after re-ingest. Existing `assess_staged_basis` establishes graph/association comparison and retained availability only; it is not live freshness proof. Use bounded safe working-tree acquisition to compare whole selected files, including bytes outside cited spans; compare supported membership/ignore inputs separately. Exact local `capture_git` establishes the bound historical commit, not requested-current revision. No fetch, HEAD fallback or newest-text substitution.

A changed selected fact, association, source bytes or relevant configuration is `stale`, even if graph identity is equal. Contradictory observations or an observed race are `conflicted`. Missing/unavailable/unsupported checks yield `unknown` unless a known change already establishes stale; expose every failed check. A changed recovered snapshot with incomplete closure is stale pending reconciliation, without asserting every fact changed. `current` requires all declared relevant inputs and dependency/configuration closure verified equal; missing configuration closure prevents a full current claim. Current producers therefore normally yield an honest incomplete/unknown packet. Working-tree acquisition is not an atomic filesystem snapshot; managed guards cover participating processes only. Report currentness as a scoped observation, never an enduring lock against editor changes.

## Bounds and local flow

Hard limits: 64 typed facts, 64 selected interpretation decisions, 4 artifacts, 16 registrations/configuration entries each; 12 excerpts, 8 KiB per span and 48 KiB total text; 128 MiB complete-file validation work, charged before reads; 4 KiB per narrative field, 64 items per work/acceptance collection, 8 KiB review note. Full artifact content UTF-8 bytes plus exact JSON-serialized complete assertion-array bytes totals at most 512 KiB across selections; canonical body at most 896 KiB and complete get/IPC response at most 1 MiB (reserve envelope space and enforce the full response bound before storage). Generation request at most 128 KiB; list pages at most 50 entries/64 KiB; Markdown export at most 4 MiB. Reuse existing snapshot ceilings (32 MiB/50,000 rows/depth32/1,000,000 values). Packet JSON preflight limits depth40/65,536 values, 64 keys per protocol object. Reject overflow before oversized allocation/persistence; no silent truncation. Bound lineage traversal to 1,024 ancestors and return limit failure beyond it.

Local IPC commands are `generate_work_packet`, `list_work_packets`, `get_work_packet`, `review_work_packet`, `assess_work_packet`, `export_work_packet`. Workers perform bounded storage/assembly; no source paths arrive as read authority. Structured errors distinguish invalid input, limit exceeded, selection conflict, review conflict, unavailable evidence and storage failure. Generation/get may succeed with explicit evidence omissions; corrupt packet bodies fail closed.

Add explicit “Add selected fact to packet” in Atlas/App node/edge inspection and “Add artifact to packet” in SpecWorkbench, and selection of existing historical assertion-decision records, with a visible removable selection tray leading to the intent form. A raw JSON form alone does not satisfy the route. Selection exposes typed references/digests and expected artifact identities. Rejected inferred assertions suppressed by normal spec export remain selectable through recovered graph inspection; do not derive all eligible selections from artifact-visible assertions. A packet form labels intent as requested, allows explicit unknown fields, generates and opens the resulting saved packet. Detail shows seven groups, body identity/lineage, independent freshness/review/execution, and limitations; revision-bound review reports conflicts. List/reopen use the saved body, never regenerate it. Shared validated presentation data feeds UI and deterministic Markdown export; export includes body identity, lineage and separately labeled review/freshness observations. User chooses a local destination through existing app conventions; the browser or WebView manages any destination and overwrite confirmation, and the UI reports only that the download was requested. Render source strings as text, escape Markdown/HTML, disable active embedded content/links that execute code. No route invokes providers, shell, GitHub, target writes or authorization changes.
