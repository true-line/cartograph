A read-only MCP client in a complete session can now read the curated projection. `curated` is readable with the artifact tool and is byte for byte the `curated.md` an export holds for the same reviews, graph and export mode. `curated-json` gives the same projection as data: the view, the curated revision, the graph basis, each accepted proposal with its record id, proposed relation, Gap, tier and confidence as produced, review status, source support, state and reason, the Workbench decision summary and the counts. A `verified-only` service shows no curated item, only how many it left out. The session basis now carries the curated revision, so a session over other reviews has another basis id, and `h3_curated_available` is true only where the session computed the projection. When it could not be computed, the basis and both documents give the reason and every other read still works. A Workbench decision that matches no recovered fact is one such reason: checking it needs every document compiled, which a client session does not do, and the export still shows the curated items. A review made while a session is being acquired makes that read fail as stale. Scoped sessions offer no curated read and say why, and work packets still cannot select the document. Review notes are never shown to the client.
