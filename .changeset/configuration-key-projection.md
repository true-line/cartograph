Every export now includes `configuration.md`. It lists each configuration key once for each repository, with the environment files that declare it and the source files and symbols that read it, each with tier, confidence and source span. A key that is read and never declared, and a key that is declared and never read, are marked. "Never declared" means that no environment file in the ingested sources declares the key, not that it is unset when the system runs. Files with a read whose key is not written as a literal are listed, so the document says that keys exist which it cannot name. Only key names are shown, never a value. The document states which languages are read (TypeScript, JavaScript, Python, Go, Rust, Java and Kotlin) and what is not covered: `import.meta.env`, destructured `process.env`, `"X" in os.environ`, Rust `env!`, and configuration frameworks such as Spring `@Value`, NestJS `ConfigService` and Viper. A `verified-only` export leaves out InferredWeak rows and states how many; a `best-effort` export marks them. In the Atlas, a configuration read now sits in the Server code band beside the file that reads it and shows its key instead of its id.
