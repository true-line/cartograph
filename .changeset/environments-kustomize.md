`environments.md` now covers kustomize and Kubernetes. Every kustomization file is listed as one environment, shown by the path of its file and named only when the file states a `namespace`; a base that other kustomizations include is one too, and its row says which include it. Each `Deployment`, `StatefulSet`, `DaemonSet` and `Job` manifest is a workload, with one row for each container: its image, ports, the names of its environment keys and the names of the ConfigMaps and Secrets it references, never a value. A kustomization lists the workloads its `resources` reach inside the repository. A workload that several kustomizations reach is listed once for each of them, with what that kustomization's patch files and `images` entries state for it, or "no patch stated"; nothing is applied, and the document does not say which one a deployment uses. Kubernetes workloads that no kustomization reaches have their own section. Remote or missing resources, patches that match nothing, inline and JSON patches, `target` selectors, cycles and transformers or generators such as `namePrefix` and `secretGenerator` are listed as not established. Helm charts and values files are still not read; Preflight and the coverage document now name unread Kubernetes manifests by kind (`Service`, `ConfigMap` and so on) instead of by file, and no longer list kustomization files or files that hold only the kinds that are read. Re-ingesting a repository that has kustomization files or these manifests adds the facts to its graph.
