Every export now includes `environments.md`. Each Compose file is listed as one environment, shown by the path of its file and named only when the file states a `name`: a file or folder name such as `prod` is never turned into an environment name. Under each environment are the workloads it declares, one for each service, with its image, build context, ports, the names of its environment keys, its environment files, its dependencies and its profiles, each with tier, confidence and source span. A service name that two or more Compose files of one repository declare is listed once for each declaration, with the properties that differ; the document does not say which one a deployment uses. A Compose file that cannot be read, `extends`, `include`, a YAML anchor, alias or tag, a dependency on a service the file does not declare, and an environment file such as `staging.env` whose name is the only thing that names an environment are listed as not established. Only the names of environment keys are stored, never a value. Kubernetes manifests, kustomize files, Helm charts and Helm values files are not read yet; Preflight and the coverage document now name each kind they find as present and not read. Re-ingesting a repository that has a Compose file adds these facts to its graph.
